## Changes to review

1. **Restore the search confirmation route.** `src/pages/submitted.astro` replaces the unused root `submitted.html`. Astro now emits `dist/submitted.html`; the form redirects to the clean `/submitted` URL. The shared layout and styles replace duplicated page chrome. Session-storage values are written with `textContent`. The copy describes the email already sent by the endpoint and removes the old promise that the service will keep monitoring availability. A direct visit without session context has generic copy.

2. **Keep price, taxes, and itinerary together.** In `functions/api/search.js`, trip candidates are first filtered to the selected cabin and points range. The existing preference for fewer stops, then shorter duration, is applied within that affordable set. The chosen trip supplies its own mileage cost, taxes, currency, and flight details. A summary minimum below the requested budget no longer hides a valid trip within budget. If known trips are all unaffordable, the code does not fall back to the cheaper summary. If individual trips are unavailable, summary availability is clearly labeled and no direct-flight claim is inferred. Missing taxes/currency are labeled instead of silently becoming USD zero; Qatar taxes are treated as unavailable under the provider's documented limitation.

3. **Preserve airport-local times.** The provider's time strings are parsed as wall-clock values, retaining their literal date and time. Missing/malformed values render as unavailable. Both next-day and previous-day arrival indicators work. The old airport-timezone map and double conversion have been removed. This behavior follows the [Seats.aero availability-trip documentation](https://developers.seats.aero/reference/concepts-copy), which says the returned times are already airport-local despite their `Z` suffix. Please pay particular attention to this provider-specific contract.

4. **Escape email content.** `src/lib/validation.js` provides a shared HTML escaper used by both endpoints. Search greetings and provider-controlled route/flight labels are escaped. Airline logo identifiers must be two alphanumeric characters before they enter an image URL. Inquiry's existing escaping and owner-first delivery are retained.

5. **Correct the demonstrated Bilt mapping error.** Bilt no longer implicitly searches American AAdvantage, and now includes United, Qatar, and Etihad alongside the existing supported partners. Explicitly selecting American miles still searches American. The mapping includes its verification date and [Bilt's source](https://support.biltrewards.com/hc/en-us/articles/19086448638989-Bilt-s-Transfer-Partners). This is a targeted Bilt correction, not a claim that all issuers or transfer ratios have been comprehensively refreshed.

6. **Read subsequent search pages.** The request sends the selected `cabins`, keeps the first response's `cursor`, advances `skip` by the number of raw rows received, and deduplicates availability by ID. `hasMore` controls continuation; page length is the fallback when it is omitted. Requests stay on the fixed provider endpoint. A 30-second search deadline and ten-page cap bound the work. A cap breach returns HTTP 422 asking for narrower criteria. A provider error returns HTTP 502. Neither case sends partial results as a completed search. The [cached-search API](https://developers.seats.aero/reference/cached-search) and its official OpenAPI example were checked for `cabins`, `hasMore`, `cursor`, and `skip`.

7. **Generate real list thumbnails.** `scripts/generate-thumbnails.mjs` makes 80, 160, and 240-pixel WebP variants for the 80-CSS-pixel place-list images. It processes eight images at a time. The globe uses `srcset`, `sizes`, lazy loading, and asynchronous decoding. Outputs live in ignored `public/images/thumbnails/` and are regenerated by the `predev` and `prebuild` npm hooks. Sharp 0.34.5, already present through Astro, is now an explicit build dependency. The deploy script uses `npm run build` so thumbnail generation cannot be skipped through that script.

8. **Reject malformed requests.** Both endpoints reject JSON null, arrays, primitives, and invalid field types. Search additionally validates known selection values, real calendar dates, integer point budgets, and airport/email lengths. Invalid requests stop before external service calls. Inquiry retains its existing text-length limits.

## Boundaries and follow-up decisions

- No live award-search or Resend requests were made. Provider behavior is exercised with documented shapes and synthetic fixtures. Erickson explicitly waived the live smoke test after reading Claude's review; it is no longer a release prerequisite.
- The existing approximate transfer model remains: one budget is applied across selected currencies/programs. Per-currency balances, non-1:1 ratios, card-tier eligibility, bonuses, and a complete refresh of other issuers are follow-up work.
- Review whether ten pages/30 seconds fits the actual commercial API quota and production traffic. Cloudflare dashboard rate-limit rules were not inspected or changed.
- The globe's existing 582 KB gzipped JavaScript bundle warning remains. This patch addresses the measured thumbnail cost; it does not change the 3D engine.
- Thumbnail generation runs through npm hooks. Build/development environments should use `npm run build` / `npm run dev`. When changing a place's first photo during an already-running development session, rerun `npm run thumbnails`.
- The runtime validation now expects numeric JSON point budgets and string inquiry fields, matching the current website forms. Any independent API clients sending numeric strings should be checked.
